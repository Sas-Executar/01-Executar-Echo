# Document-to-Framework Conversion

## Contents
- Extraction order
- Preservation rules
- Framework mapping
- External enrichment
- Conflict handling

## Extraction order
1. Identify document type, author/owner, date, scope and intended audience.
2. Extract explicit claims, metrics, decisions, assumptions, risks, actors, dates, dependencies and recommendations.
3. Preserve source locations.
4. Build an evidence ledger before selecting frameworks.
5. Select frameworks based on the information and intent, not on document genre alone.

## Preservation rules
Do not change the meaning of source material. Do not merge separate claims into one fact unless the relationship is explicit. Keep quoted wording minimal; prefer faithful paraphrase with location.

## Framework mapping
Map source evidence to framework fields. If a framework cell has no support, mark `EVIDENCE_GAP`. Do not infer a missing quadrant merely to complete a visual.

## External enrichment
Use web research to validate current external context, definitions, benchmarks, regulation or market evidence. Keep internal document claims distinguishable from external evidence.

## Conflict handling
If external evidence conflicts with the document, show both, identify differences in date/scope/definition and state the analytical impact. Do not silently overwrite the document.
