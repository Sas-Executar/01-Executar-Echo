# Intent Routing

## Contents
- Routing contract
- Intent signals

- Output consequences

## Routing contract
Determine the user's actual analytical objective before choosing frameworks. The same topic can require different frameworks depending on whether the user wants diagnosis, explanation, comparison, validation, prioritization, risk analysis, planning, or decision support.

## Intent signals
- RESEARCH_TO_FRAMEWORK: “pesquise”, “entenda o mercado”, “analise o negócio”, “como está o setor”.
- DOCUMENT_TO_FRAMEWORK: “converta este relatório”, “estruture estes documentos”, “resuma usando frameworks”.
- HYBRID: user files plus request for current external context or validation.
- FRAMEWORK_SPECIFIC: explicit request for SWOT, PESTEL, PMF, 5W2H etc.
- DECISION_SUPPORT: “comparar”, “escolher”, “priorizar”, “qual opção”, “riscos da decisão”.
- LEARNING_VIEW: “me explique”, “quero visualizar”, “quero entender sem relatório longo”.

## Ambiguity handling
Proceed with a bounded assumption if the missing detail is low-risk. Ask only when geography, period, population, product scope or decision target would materially change the result. If multiple plausible interpretations exist, state the chosen interpretation and keep alternatives visible.

## Output consequences
Research routes require evidence collection before analysis. Document routes require extraction before external search. Decision routes require explicit criteria and alternatives. Learning routes optimize for cognitive compression rather than exhaustive coverage.
